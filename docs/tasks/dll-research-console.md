# Local DLL research console

The user requests a localhost visual map of DLL parts, missing work, agent
assignment and usage, with commands issued from the selected part.

Own tools/dll_console/** and this task plan. Build a separate research tool;
preserve the original DJI application UI and all existing research/source scopes.
Use a dependency-free local Python server and HTML/CSS/JavaScript frontend.
Read original PE metadata, explicit evidence/review records, project bus activity,
CLI process metadata and reported usage. Distinguish static contracts, application
implementation and reference comparisons. Do not invent completion percentages.

Provide a selectable DLL/part map, binary section map, original export search,
evidence links, missing-work details and editable scoped task prompts. Queue
explicit user assignments to fixed supported Codex/OpenCode models, honor shared
worker limits and avoid duplicate active ownership. Keep job outputs isolated.
Allow cancel/resume only for console-owned jobs. Preserve other workers.
Bind only to loopback and validate local mutation requests. Never expose
credentials, private reasoning or arbitrary shell execution through the browser.

Verify PE parsing, status provenance, queue limits, input/path validation,
owned-process controls and token accounting with meaningful tests. Test the UI
through structured browser access where available. Request independent source
review of the exact candidate. Keep draft; no merge or release.
